OBSERVABILITY SHOWS USER PAIN AND CONTAINMENT

[06]
[CONTEXT] Operational dashboards should support investigation; alert decisions remain tied to the BFF’s bounded refresh and health signals.
[01]

USER-IMPACT SIGNALS

Track refresh outcome, refresh duration, provider-unavailable count, lease contention, BFF readiness, and PostgreSQL health. Measure the contract that users experience—not only pod liveness.

[02]

ALERT ON SUSTAINED FAILURE

Page when user-visible refresh failures remain above the approved threshold for the configured duration. Warn earlier on rising contention, circuit-open state, and scrape degradation.

[03]

KEEP LABELS SAFE

Use bounded labels such as outcome and provider category. Never emit user ID, session ID, token, email, authorization code, PKCE verifier, or raw provider error text.

TELEMETRY RULE
Metrics prove containment and recovery. Logs preserve a redacted correlation trail. Neither becomes a second token store.
