STRIDE FOCUSES DEFENSES ON REFRESH TRUST BOUNDARIES

[07]

[BOUNDARY]
BROWSER → PROXY → BFF → KEYCLOAK / POSTGRESQL / KMS

STRIDE AREA
REFRESH-SESSION THREAT
[S]
SPOOFING
Forged BIS cookie, callback mix-up, issuer substitution, or subject mismatch.
[T]
TAMPERING
Altered lease/version row, token ciphertext, redirect state, or feature flag.
[I]
DISCLOSURE
Refresh material exposed through browser storage, logs, metrics, traces, or backup access.
[D]
DENIAL
Refresh storm, lease starvation, provider outage, callback flood, or database failover.
[E]
PRIVILEGE
Token subject/role drift permits an unauthorized privileged action after rotation.
PRIMARY CONTROL
PKCE S256, one-time state/nonce, strict issuer/audience/subject validation, hardened cookie.
AEAD encryption, PostgreSQL compare-and-swap lease, least-privilege roles, immutable provenance.
No browser refresh token; redaction; bounded metric labels; private telemetry and encrypted backups.
Single-flight lease, timeout, circuit breaker, rate limit, HPA/PDB, staging-only fault policy.
Subject binding, fresh assurance for sensitive actions, role revalidation, dual control for global invalidation.
DECISION RULE: Every identified threat must map to an enforceable BFF control, a negative test, and an observable signal—otherwise it remains an unmanaged risk.
