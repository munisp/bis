# Distributed Tracing, Refresh-Race Diagnostics, and Authentication Edge Hardening

**Author:** Manus AI  
**Status:** Implementation reference. The current BIS codebase has request IDs and audit structures but does not yet contain the OpenTelemetry bootstrap or database schema described below. Treat the TypeScript and Helm/YAML examples as the target implementation, not as already-deployed behavior.

## 1. Design Goals and Non-Negotiable Boundaries

The objective is to diagnose simultaneous browser-tab refresh attempts without turning observability into a credential store. A refresh trace must let an operator answer: *which request acquired the lease, which requests waited, what Keycloak outcome occurred, and what PostgreSQL compare-and-swap decision ended the race?* It must **not** contain an access token, refresh token, authorization code, PKCE verifier, cookie, email address, raw provider body, or SQL parameter value.

OpenTelemetry context propagation maintains causal relationships across processes and allows logs to carry trace/span identity; the default propagator uses W3C TraceContext headers. [1] Use the standard `traceparent` and `tracestate` headers for service-to-service correlation, while using an independently generated **opaque operation ID** for support/audit joins. Never place user IDs or session-family IDs in `tracestate`, baggage, or a URL.

```text
browser tab A          nginx / ingress          BFF pod A          PostgreSQL        Keycloak
    |                    traceparent ->        refresh root ->    lease span ->      exchange span ->
    |-- session cookie --> (overwrite client    operation_id        CAS update         traceparent
    |                    x-request-id)          hash-only attrs     version row        no credentials
browser tab B --------> same trace discipline; may land on BFF pod B and observe lease-held outcome
```

| Identifier | Generated by | Allowed to leave BFF? | Retention | Safe contents |
|---|---|---:|---|---|
| `trace_id` | OpenTelemetry SDK or trusted incoming W3C context | Yes, as W3C header | Trace retention policy | Random opaque identifier. |
| `span_id` | OpenTelemetry SDK | Yes, within W3C context | Trace retention policy | Random opaque identifier. |
| `operation_id` | BFF at refresh entry | Response header and audit/log event only | Incident/audit policy | UUIDv7 or random opaque ID. |
| `request_id` | Trusted proxy or BFF | Response/log only | Access-log policy | Random opaque ID; overwrite client value. |
| `session_family_hash` | BFF HMAC of internal family ID | Logs/traces/audit only | Security-retention policy | Keyed pseudonym; never raw family ID. |

## 2. Trace Flow for a Concurrent Refresh Race

### 2.1 Step-by-step execution narrative

1. A client receives `401` on a protected API call. The browser performs **one** BFF refresh request through its local single-flight coordinator. It does not read or send a refresh token.
2. The proxy validates the host and TLS path, overwrites untrusted forwarding/request headers, forwards the BFF cookie, and creates or forwards a trusted W3C trace context.
3. The BFF extracts the W3C context, creates `auth.refresh` as a server span, generates `operation_id`, and derives a keyed `session_family_hash` only for telemetry.
4. The BFF performs one compare-and-swap lease update. The winning request records `lease.acquired=true`; a losing request records `lease.result=held` and returns the documented bounded result rather than calling Keycloak.
5. The winner starts a nested PostgreSQL span for the lease update and a nested Keycloak span for token rotation. It injects only W3C context into the Keycloak HTTP request. Keycloak may log or discard that header; the BFF still has end-to-end timing around the outbound call.
6. On success, the BFF atomically persists the new encrypted refresh material and version, clears the lease, emits a non-sensitive audit event, sets only its HttpOnly session cookie, and returns `204` plus `x-operation-id`.
7. On provider timeout or a rejected refresh, the BFF records a stable category—not the raw response body—clears/sets the lease exactly per policy, and returns a safe error. The browser either waits, retries once after a documented `Retry-After`, or signs the user out. It never improvises a browser-held token fallback.

### 2.2 Span hierarchy and attributes

| Span | Parent | Essential safe attributes | Never record |
|---|---|---|---|
| `http.server.request` | Incoming context | Route template, method, status code, trusted request ID. | Query strings containing state/code, Cookie, Authorization. |
| `auth.refresh` | HTTP server span | `auth.outcome`, `auth.lease_result`, `auth.session_family_hash`, `auth.operation_id`. | User ID, email, session ID, refresh version raw value if linkable. |
| `db.refresh_lease.cas` | Refresh span | Table name, operation category, rows affected, lease result, duration. | SQL text with literals, token ciphertext, parameters. |
| `http.client.keycloak.token` | Refresh span | Peer service, route category, HTTP status, timeout boolean, duration. | Form body, authorization code, verifier, access/refresh token, provider body. |
| `db.refresh_rotation.persist` | Refresh span | Transaction outcome, rows affected, encryption key version. | Encrypted token, nonce, tag, session data. |
| `auth.audit.write` | Refresh span | Immutable event type, operation ID, decision source. | Credential material and personal data. |

### 3.1 Bootstrap telemetry before importing the HTTP server

```ts
// server/_core/telemetry.ts
import { OTLPTraceExporter } from "@opentelemetry/exporter-trace-otlp-proto";
import { getNodeAutoInstrumentations } from "@opentelemetry/auto-instrumentations-node";
import { NodeSDK } from "@opentelemetry/sdk-node";
import { Resource } from "@opentelemetry/resources";
import { ATTR_SERVICE_NAME, ATTR_SERVICE_VERSION } from "@opentelemetry/semantic-conventions";

const endpoint = process.env.OTEL_EXPORTER_OTLP_TRACES_ENDPOINT;

export const telemetry = endpoint
  ? new NodeSDK({
      resource: new Resource({
        [ATTR_SERVICE_NAME]: "bis-bff",
        [ATTR_SERVICE_VERSION]: process.env.GIT_SHA ?? "unknown",
        "deployment.environment.name": process.env.DEPLOYMENT_ENVIRONMENT ?? "unknown",
      }),
      traceExporter: new OTLPTraceExporter({ url: endpoint }),
      instrumentations: [
        getNodeAutoInstrumentations({
          "@opentelemetry/instrumentation-http": {
            ignoreIncomingRequestHook(request) {
              // Health/metrics cannot become an auth-trace noise source.
              return request.url === "/healthz" || request.url === "/metrics";
            },
          },
        }),
      ],
    })
  : undefined;

export async function startTelemetry() {
  await telemetry?.start();
}
```

Call `await startTelemetry()` **before** importing modules that initialize Express, the database client, or outbound HTTP clients. Explicitly configure the SDK sampler and exporter network policy. Do not silently export traces to a public endpoint.

### 3.2 Safe refresh-operation instrumentation

```ts
// server/_core/refreshTracing.ts
import { context, propagation, SpanStatusCode, trace } from "@opentelemetry/api";
import { createHmac, randomUUID } from "node:crypto";

const tracer = trace.getTracer("bis.auth.refresh");

function pseudonymize(value: string): string {
  const key = process.env.TELEMETRY_PSEUDONYMIZATION_KEY;
  if (!key) throw new Error("TELEMETRY_PSEUDONYMIZATION_KEY is required when tracing refreshes");
  return createHmac("sha256", key).update(value).digest("base64url").slice(0, 22);
}

export async function traceRefresh<T>(input: {
  sessionFamilyId: string;
  run: (scope: { operationId: string; injectKeycloakHeaders: (headers: Headers) => void }) => Promise<T>;
}): Promise<T> {
  const operationId = randomUUID();
  return tracer.startActiveSpan("auth.refresh", async span => {
    span.setAttributes({
      "auth.operation_id": operationId,
      "auth.session_family_hash": pseudonymize(input.sessionFamilyId),
      "auth.flow": "bff_owned_rotation",
    });
    try {
      const result = await input.run({
        operationId,
        injectKeycloakHeaders(headers) {
          propagation.inject(context.active(), headers, {
            set(carrier, key, value) { carrier.set(key, value); },
          });
        },
      });
      span.setStatus({ code: SpanStatusCode.OK });
      return result;
    } catch (error) {
      // Normalize first; never add raw error text if it can contain provider response data.
      span.setAttribute("auth.error_class", classifyRefreshError(error));
      span.setStatus({ code: SpanStatusCode.ERROR });
      throw error;
    } finally {
      span.end();
    }
  });
}
```

`classifyRefreshError` should return a small allowlist such as `lease_held`, `provider_timeout`, `provider_rejected`, `session_revoked`, `database_unavailable`, or `internal`. Log a sanitized error code and `operation_id`; preserve raw provider diagnostics only in the restricted incident evidence store after credential redaction.

### 3.3 Correlating two BFF pods without a distributed token

The database row is the authority, not the trace system. Add safe race fields to `refresh_session_lease` or its adjacent persisted session table:

```sql
ALTER TABLE refresh_session_leases
  ADD COLUMN IF NOT EXISTS last_operation_id uuid,
  ADD COLUMN IF NOT EXISTS last_trace_id text,
  ADD COLUMN IF NOT EXISTS last_outcome text;

CREATE INDEX CONCURRENTLY IF NOT EXISTS refresh_session_leases_operation_idx
  ON refresh_session_leases (last_operation_id);
```

Store the `trace_id` only if its retention and access model is consistent with your security policy; it is opaque but can be an observability join key. The compare-and-swap statement must return enough non-sensitive diagnostics to annotate the span:

```sql
UPDATE refresh_session_leases
SET lease_owner = $1,
    lease_expires_at = now() + interval '15 seconds',
    last_operation_id = $2,
    last_trace_id = $3,
    last_outcome = 'lease_acquired'
WHERE session_family_id = $4
  AND revoked_at IS NULL
  AND (lease_expires_at IS NULL OR lease_expires_at < now())
RETURNING session_family_id, lease_expires_at, version;
```

If `RETURNING` yields no row, read a constrained diagnostic projection (`lease_expires_at`, `last_operation_id`, `last_outcome`) under the same transaction policy. Do not return it to the browser. Attach it to the trace as safe attributes and emit only `operation_id` to the response header.

### 3.4 Querying a race investigation

An operator starts with the **opaque** `x-operation-id` from an error report, locates the audit event, then pivots to the trace and normalized lease outcome. Do not search by refresh token or cookie.

```text
operation_id
  → audit event (actor class, outcome, UTC, approval/revocation state)
  → trace_id (BFF CAS + Keycloak outbound durations)
  → session_family_hash (telemetry only)
  → lease diagnostic (winner/held/expired/revoked)
```

## 4. Nginx Proxy Hardening Checklist

Apply the checklist in a separately reviewed Nginx configuration. The proxy is a trust boundary: it must overwrite client-supplied forwarding headers and never treat a random public client as the source of identity context.

| Control | Required configuration/behavior | Verification |
|---|---|---|
| TLS and host routing | Redirect HTTP to HTTPS, use maintained certificates, set a canonical host, and reject unknown hosts. | Test HTTP redirect, SNI mismatch, unknown Host, expired-certificate alert. |
| Proxy headers | Overwrite `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Host`, and `X-Request-ID`; pass a valid W3C context or generate a new one. | Send malicious client headers and confirm BFF receives only trusted values. |
| Cookie protection | BFF emits `Secure; HttpOnly; SameSite=Lax` (or a documented cross-site alternative); Nginx never logs or rewrites token-bearing values. | Inspect `Set-Cookie`; test cross-site callback and CSRF rejection. |
| Callback route | Limit body size, disable caching, use a short explicit upstream timeout, and permit only expected GET/POST method(s). | Oversize body, invalid method, cache probe, delayed upstream tests. |
| Refresh route | Same-origin requests only, strict CORS deny-by-default, bounded request body, per-IP coarse limit plus BFF session-family control. | Cross-origin fetch, burst, stale cookie, and NAT-aware limit tests. |
| Response safety | Disable version leakage, custom error pages, `Cache-Control: no-store` for auth endpoints, CSP for auth-rendered HTML. | Scan 4xx/5xx and headers. |
| Log hygiene | Log method, route template, status, duration, trusted IDs; redact Cookie, Authorization, state, code, and query strings. | Deliberate redaction regression test. |
| Upstream boundary | Private BFF Service only; Nginx uses a dedicated upstream, health check, bounded keepalive, and no direct public BFF port. | Network scan / NetworkPolicy test. |

```nginx
# nginx/conf.d/bis-auth.conf
map $http_traceparent $trusted_traceparent {
  default $http_traceparent; # Replace with validated W3C format or generated context in a hardened module.
  ""      $request_id;
}

server {
  listen 443 ssl http2;
  server_name bis.example.com;
  server_tokens off;

  add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
  add_header X-Content-Type-Options "nosniff" always;
  add_header Referrer-Policy "no-referrer" always;
  add_header X-Frame-Options "DENY" always;

  location ~ ^/api/auth/(keycloak/callback|refresh)$ {
    proxy_pass http://bis_bff;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Request-ID $request_id;
    proxy_set_header traceparent $trusted_traceparent;
    proxy_set_header Authorization "";

    client_max_body_size 32k;
    proxy_connect_timeout 5s;
    proxy_read_timeout 15s;
    proxy_send_timeout 15s;
    proxy_buffering off;
    add_header Cache-Control "no-store" always;
  }
}
```

**Important:** `$request_id` is not a W3C `traceparent`. In a production implementation, validate a received W3C header against the required format or generate it at the BFF/telemetry layer. Do not substitute arbitrary client data into trace headers.

## 5. Kubernetes Ingress Controller and Ingress Hardening Checklist

The ingress-nginx project explicitly warns that its model assumes users who can create Ingress objects are cluster administrators; do not use an unconstrained shared controller as a cross-tenant security boundary. [2]

| Layer | Hardening requirement | Acceptance evidence |
|---|---|---|
| Controller ownership | Dedicated auth-facing IngressClass/controller or tightly restricted namespace/Ingress RBAC; `allow-snippet-annotations: "false"`. | RBAC test proves app namespaces cannot add arbitrary Nginx snippets. |
| TLS | `cert-manager` certificate, TLS redirect, modern protocol/cipher policy reviewed against client support, HSTS after validation. | TLS scan and certificate renewal drill. |
| Trusted source IP | Configure forwarded headers only behind a known load balancer and correct `proxy-real-ip-cidr`; otherwise do not trust client forwarding fields. | Spoofed XFF test and source-IP audit. |
| Error disclosure | Custom error handling; hide `Server` and `X-Powered-By`; no debug annotations. | 400/403/429/500/503 response scan. |
| Authentication routes | Separate `auth` Ingress with small body limit, short timeout, no cache, no unsafe snippets, restrictive methods at BFF, rate-control strategy. | Route-specific policy test. |
| Network isolation | Ingress can reach BFF; BFF can reach Keycloak/database/collector only; no public database/collector path. | Namespace NetworkPolicy and negative connectivity test. |
| Runtime hardening | Non-root controller/BFF, read-only filesystem where compatible, dropped capabilities, seccomp, resource limits, probes, PDB, image provenance. | Admission policy / runtime manifest scan. |
| Observability | Trusted request/trace identifiers; redacted logs; protected metrics; alert on TLS/cert errors, 401/429 anomalies, upstream timeout, and WAF/controller errors. | Synthetic alert delivery test. |

```yaml
# Helm values fragment — reviewed by the platform/Ingress administrator
controller:
  config:
    allow-snippet-annotations: "false"
    server-tokens: "false"
    hide-headers: "Server,X-Powered-By"
    ssl-protocols: "TLSv1.2 TLSv1.3"
    hsts: "true"
    hsts-max-age: "31536000"
    hsts-include-subdomains: "true"
    use-forwarded-headers: "true" # Only when behind a known trusted load balancer.
    compute-full-forwarded-for: "true"
  service:
    externalTrafficPolicy: Local
  admissionWebhooks:
    enabled: true
```

```yaml
# charts/bis/templates/ingress-auth.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: bis-auth
  namespace: bis-production
  annotations:
    kubernetes.io/ingress.class: bis-auth
    cert-manager.io/cluster-issuer: letsencrypt-production
    nginx.ingress.kubernetes.io/force-ssl-redirect: "true"
    nginx.ingress.kubernetes.io/proxy-body-size: "32k"
    nginx.ingress.kubernetes.io/proxy-connect-timeout: "5"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "15"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "15"
    nginx.ingress.kubernetes.io/proxy-buffering: "off"
    nginx.ingress.kubernetes.io/limit-rps: "20"
    nginx.ingress.kubernetes.io/limit-burst-multiplier: "3"
spec:
  ingressClassName: bis-auth
  tls:
    - hosts: ["bis.example.com"]
      secretName: bis-public-tls
  rules:
    - host: bis.example.com
      http:
        paths:
          - path: /api/auth
            pathType: Prefix
            backend:
              service:
                name: bis-bff
                port:
                  name: http
```

Ingress rate limits are coarse edge protections, not the refresh concurrency authority. The BFF's PostgreSQL lease/version control remains authoritative because IP-based limits cannot distinguish multiple legitimate users behind a NAT and cannot coordinate requests that land on different BFF pods.

## 6. Validation Matrix

| Test | Expected result | Failure indicates |
|---|---|---|
| Two tabs, two BFF pods, one session family | Exactly one Keycloak rotation; losing request has `lease_held`; trace joins by operation/trace IDs. | Lease CAS, propagation, or retry policy defect. |
| Malicious `X-Forwarded-*`, `X-Request-ID`, `traceparent` | Trusted proxy/BFF behavior overwrites or safely validates input; no spoofed audit attribution. | Edge trust-boundary defect. |
| Keycloak delay/loss drill | Bounded Keycloak spans, normalized provider outcomes, no retry storm, alert/recovery evidence. | Timeout/circuit/lease/observability defect. |
| Callback containing code/state | No value appears in proxy log, BFF log, trace attribute, metric label, browser telemetry, or error response. | Secret-redaction defect. |
| Ingress error probe | Generic custom response; no version/upstream topology; cache disabled for auth endpoints. | Information-disclosure or cache defect. |
| Metrics probe | `/metrics` cannot be scraped publicly; trace exporter only reaches approved collector endpoint. | Telemetry exposure defect. |
